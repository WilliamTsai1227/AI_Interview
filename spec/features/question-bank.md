# 面試題庫

## 為什麼做

使用者常常知道「這家一定會問某件事」，或想多練自己弱的類型。AI 出的題目不一定剛好是他要的，所以題庫要能**自己掌控**：加題、改題、刪題、排順序、決定要不要追問。

模擬面試會照題庫的順序提問。

## 怎麼用

- 在題庫頁輸入需求（例如「多問帶人和 Code Review」），選類別、難度、題數，按「生成題目」。重複的題目會自動略過。
- 每題可以編輯文字、類別、難度，上下移動調整順序，刪除。
- 自己新增題目。
- 每題設定追問方式：不追問、固定追問幾次、預設好的追問題、Ava 自己判斷（最多幾次）。
- 面試報告裡的弱項可以一鍵加回題庫（放在最前面）。

### AI 工程職缺：AI 系統設計知識表

職缺看起來是 AI／LLM 工程職缺時（職稱或內容出現 LLM、RAG、機器學習、AI 工程等），出題、Live 面試官簡報、面試建議、追問、評分都會參考一份「AI 系統設計知識表」（`backend/app/ai/knowledge/ai_system_design.py`）：

- 18 個主題（RAG、向量資料庫、推論部署、延遲與成本估算、快取、模型路由與 Gateway、context 管理、Agent、多 agent、串流與非同步、護欄與隱私、評估、監控與容錯、微調、推論最佳化、語音與多模態、結構化輸出、多租戶），每個主題寫「面試官看什麼、常見題型、追問方向、常見錯誤」。
- 解題八步驟：需求 → AI 要做的事 → 資料 → 架構 → 模型與 prompt → 評估 → 部署與擴充 → 監控。系統設計題的評分會對照這些步驟，指出缺了哪一步；數字只看推導過程，不因為和模型知道的數字不同就扣分。
- 依職缺文字挑最相關的 3–5 個主題放進 prompt（追問只放 2 個主題的追問方向，避免拖慢 3 秒內的回應）；一般職缺完全不受影響。
- 內容整理自 [amitshekhariitbhu/ai-system-design](https://github.com/amitshekhariitbhu/ai-system-design)（Apache-2.0），用我們自己的話重寫。

## 怎麼測試

- AI 工程職缺：系統設計題要有具體規模（使用者量、延遲、預算）和這家公司的產品情境；後端、前端職缺的題目不應出現 AI 系統設計內容（`tests/test_ai_system_design.py`）。

**功能**
- 生成 5 題 → 題數正確、沒有跟現有題目重複。
- 編輯、刪除、排序後重新整理頁面，結果有保留；模擬面試的出題順序跟題庫一致。
- 設成「不追問」的題目，面試時真的不會追問；「固定 2 次」就追問 2 次。

**效果**
- 題目的類別和難度符合選擇；「進階」題應該問到取捨和細節，不是定義題。
- 輸入的需求有被反映在新題目裡。
